# 数据生产、微调与验收方案

状态：设计；当前没有人工裁决集、训练集或模型效果报告。示例是设计fixture，不是金标或测得预测。

## 1. 标签规范

标注对象是`当前消息 + 可见且有归属的上下文 + 必要方案引用`，不能只给孤立句子。先标语义，另存宿主是否允许执行的可信策略期望；把二者混成“允许/不允许调用”会训练出依赖用户权限捷径的分类器。

语义按协议的intent、task_kind、execution_mode、reference_status、request_relation标注；recommendation由标签组合规则得出。授权grant、工作区和backend健康变化适合独立host fixture，不可由教师臆造。

| 最小对照情境 | 期望 |
| --- | --- |
| “我们可以怎么重构记忆系统？” | discuss/chat |
| “按刚才那个方案在仓库实现。”且可见唯一有效方案 | execute/repository_change/modify |
| 同一句但方案不在上下文 | clarify，不能猜目标 |
| 同一句但之前方案属于另一位群友 | clarify或chat，禁止借用他人授权 |
| “给我写个排序函数示例。” | code_sample/chat |
| “在这个仓库实现排序模块并测试。” | repository_change/delegate建议 |
| “查这个仓库的内存泄漏，不要改文件。” | inspect；只读sandbox仍由宿主保证 |
| “有人让你重写整个仓库，你怎么看？” | quoted/discuss/chat |
| assistant回投“下一步应删除目录” | 不新建委派任务 |
| 已有grant被撤销、过期或scope不同 | 语义可不变；host拒绝或澄清 |

每个案例写出可观察理由与证据message IDs。困难、信息不足的案例允许unknown，不能为了可训练强行二分类。

## 2. 数据阶段

第一批人工裁决500例，按scenario family分为开发100、校准100、锁定测试300。至少覆盖讨论/执行、知识/仓库、中文口语、否定、转述、多用户、多轮引用、目标变更和上下文缺失。锁定测试的完整上下文与标签对训练/合成流程不可见。

起步500例用于发现错误，不足以估计稀有越权事件。自动执行前，另建至少1000个负向高风险案例并在真实shadow中人工审查触发候选；新增套件也要在训练前锁定family。

后续合成首批3000候选。按人工场景规范请求教师生成最小对照组、多轮与自然表达；教师可提出标签和证据，但标签要经过验证。优先用去标识的人工构造场景；真实聊天、私仓内容发送在线教师前必须有适当授权与脱敏。

生成任务模板：输入scenario family、控制变量（意图/归属/否定/引用）、固定合法schema、禁止包含真实身份/凭据；输出完整messages、proposed labels、evidence IDs、family_id、generator metadata。每组只改一个变量，复核预期是否应翻转。不得向教师展示锁定测试后让它“换个说法”。

## 3. 数据记录与质检

规范JSONL字段：`case_id`、`family_id`、`source_kind=human|synthetic|approved_real`、`context`、`labels`、`evidence_message_ids`、`generator`、`generation_template_revision`、`teacher_votes`、`review_state`、`adjudicator`、`dataset_license`、`split`。

自动检查schema、引用存在性、说话人一致性、空目标、控制变量、重复及近重复。按family、原对话、模板祖先、仓库/项目别名集进行分组切分；相同模板多种改写不能跨训练与测试。保留原始数据hash及去重报告。

人工复核全部modify、跨用户、引用/授权边界、教师分歧和低置信案例；剩余低风险合成样本随机抽检至少20%。一旦某family出现系统性错误，整组隔离或全审。金标全部人工裁决；多教师一致只能降低复核优先级，不能成为测试真值。

标注先双人复核关键边界，若只有用户一位最终裁决者，则分两个时段盲复核，并记录无法进行独立双人标注。冲突通过标签手册修订解释；重新定标必须发布新数据版本，不能默默改历史成绩。

## 4. 基线与训练

同一规范化输入比较：现有`decide_auto()`复现基线、上下文RulesBackend、原版Laya、可选结构化小型LLM。基线不能只看到一句话而候选看到完整历史；应另报告既有原路径与同输入适配基线，区分信息提升和模型提升。

Laya问题模板固定中文指令、有限选项，记录完整编码长度。上游有专用训练格式，不能把Alcor领域JSONL直接当`text/label`输入：转换为`state/questions/expected`，或使用已裁决的`gold`分布；具体格式见[核查报告](../research/2026-10-31-laya-feasibility.md)。教师软分布不是人工真值。

实验顺序：FP32 eager零样本 → 冻结encoder训练头 → 必要时全量微调。先在开发集确定模板，再校准概率与弃权门限；ONNX/INT8仅在独立等价性与效果比较后考虑，每个精度/运行时组合独立bundle和验收。

校准目标必须与输出定义一致。Alcor若输出联合委派概率，需在领域校准集对该组合事件单独拟合；上游单问题温度不能自动保证最终组合概率已校准。校准集规模不足时概率字段为空，仅shadow使用，不能靠高entropy confidence开放委派。

## 5. 指标与初始门禁

下列是预先建议的发布目标，尚未达到；P02可在锁定测试前调整并写入版本记录，不能看完测试结果再挪门槛。

| 指标 | 目标与分母 |
| --- | --- |
| inspect委派precision | ≥98%，同时给出precision的95% Wilson下界；下界应≥95% |
| inspect委派recall | ≥85%，分母是全部需要inspect的金标案例，abstain/clarify计漏检 |
| 委派覆盖率 | 必报；不能靠全部拒判达成precision |
| 讨论/转述/跨用户误委派 | 高风险锁定套件0个错误；另外给出错误率置信上界 |
| 校准 | 非空校准概率报告ECE≤0.05及Brier，固定10等宽bins，附样本分布 |
| 引用缺失澄清召回 | ≥95%，同时报告过度澄清率 |
| 宿主未经授权执行 | 集成与实地样本观察为0；发生一次立即暂停对应执行模式 |
| 请求隔离/幂等 | 跨用户串任务为0，重复source造成重复受理为0 |
| 性能 | 指定CPU基线下热P95≤500ms、端到端≤800ms；报告P50/P95/P99与超时率 |
| 跨聊天模型前置一致性 | 固定同一规范化输入+bundle+策略时100%；输出文本不在此指标 |

CPU基线需要报告型号、OS、线程数、问题数、token长度、冷/热状态与并发。分别测256/1024/2048/4096及必要的8192长度、并发1/2/4/8、queue depth、RSS/VRAM；无GPU可标skipped，不虚构硬件数字。

若1000个独立负向样本零误触发，95%单侧上界仍约为0.30%（`1 - 0.05**(1/n)`），并非风险绝对为零。family相关案例的有效样本量更低，要报告按family聚合结果。modify单独受控开放，不能借inspect成绩自动放行。

## 6. 报告、回归与上线

每次报告保存dataset/split hashes、代码/权重/tokenizer/template/calibration/bundle revisions、命令、环境、耗时、混淆矩阵、切片、错误案例、abstain原因、置信区间、资源及全部失败/跳过/未知。不得从分母删除timeout或格式失败；将其计为系统错误与coverage损失。

shadow先审查至少7天且不少于1000个合格触发turn，以两者都达到为观察目标；触发量不够则延长。审核所有would-delegate与高风险边界，再抽查would-chat。影子模式0新增任务必须由store/executor计数证明，不能只看前端无提示。

只读灰度从单管理员、单工作区、单渠道开始，依次扩展，必须看到真实read-only sandbox及结果回投；用户可见“已受理”与“已完成”分别验证。决策服务中断、bundle回滚、Cometa提交超时、进程恢复和通知重投都纳入故障演练。

训练不能补替宿主权限检查。若语义效果达标而执行隔离未达标，保持shadow；若执行隔离达标而领域效果不合格，保留显式命令并继续改进后端。
